## 1. 冻结什么、交付什么

以下数值继承 B V3，不因本次历史盈利选择或修改：

- 两币、1x、无借贷、单一共享 1000 USDT 模拟资本；base 和 stress 各有自己的账本，二者是同一候选成本情景，不能二选一或当独立重复。
- 连续完整 UTC 日 `t-84..t` 的 85 日依赖；`close[t]>close[t-84]` 为正，等于也属非正。ATR 为 20 日 true range 算术均值，固定初始 stop distance=3×ATR；信号只在下一日 00:00 使用已闭市信息，最早 01:00 原始 open 执行，不改成当日收盘成交。初次正信号可入，stop/84×24h 到期后须非正再转正。B 不使用 C 的 273 日依赖。
- 每币 0.5% NAV 初始 stop-risk cell；共享按比例缩量、向下 lot；40% 每币/80% 总名义上限，现金和既有库存均参与约束。10% 观测回撤锁存后降低既有仓位并将 cell 降到 0.25%；15% 锁存永久禁止新买，仍按原规则处理持仓/退出，**并非保证立即全平**。20% 是用户风险上限，遇到穿越如实报失败，不保证缺口中能守住。峰值和锁存不重置。
- base 每边 fee .001/slip .0006；stress .002/.0012（继承公开保守模型假设，不是账户费率）。买价向上 tick，买量向下 lot，手续费向上 base commission precision 从收到的 base 扣；卖价向下 tick、quote fee 向上 quote precision。期末保留库存/basis，假设退出成本另列，没有虚构最终清仓。
- V3 residual 仅在无法构成合法卖单且其全部标值不超过现有每币 risk cell 时可结束 active episode；残余仍进 NAV、basis、40/80 上限。再次可卖时先清理；正常新 episode 的预算先扣旧 residual 的全损额；不为清 dust 补买。较大不可卖仓、待退出、STALE、超上限、执行/会计错误均禁止新风险。
- 保留 `SpotResidualV3`、`signal`、`ReconcilerV3` 和操作次数驱动的精度拒绝界，不因误差或亏损扩大界。native 固定 Freqtrade 2026.7、commit `52bc96f4480b1a0da6a9b455bd00b17fbb6786a5`，CCXT 4.5.68；Python 3.13.13 为已验证环境。native 只是已验证的离线映射依赖，前向首次方案不实例化它。

可携带包只保留这条执行/解释链的代码、复算入口和少量合成检查；采集 v1/v2/v3、分页续接、旧预算恢复脚本留在 PR 的历史证据中，不成为前向生产依赖。`run_spot139_v3.py` 是已消费历史的复算来源，仍硬绑定旧绝对路径/窗口/祖先 SHA；它**不是可搬迁即运行的前向入口**，原 manifest 已因终态 checkpoint 漂移而应拒绝再次执行。可移植的是冻结代码及合成验证，不伪称已有可用日增量 runner。

下一项工程依赖只需一个显式 CLI：输入当天已验收的小时包和上次状态，调用同一 `SpotResidualV3.on_hour`，输出当天状态/日志；不导入旧采集链、不加数据库/服务。尚未实现或获准，不能拿旧历史 runner 换一个日期启动。索引给出现有可运行的合成入口、报告复核入口及失败行为。

## 3. 每天一次的最小作业与有限预算（全部为待核准建议）

每天 UTC 00:10（北京时间 08:10）由已有监督 heartbeat 协调一次有限 CLI，处理上一完整 UTC 日。这必然是 **冻结规则的延迟模拟观察**：模型按小时因果顺序重放当天 open 和此前 completed-low，但接收/计算实际发生在次日；日志同时记 source event time、received_at、computed_at，并标 `DELAYED_OBSERVATION`。它不证明当天 01:00 曾实时发出模拟单，更不证明真实止损及时执行。正常每日批处理也如实标延迟，Mac 漏跑后补到的数据额外标补采。

每次顺序任务：先验证候选文件/当前登记/预算/上次状态 SHA 和单 writer 锁；公开 metadata 两币一次，比较冻结的 SPOT 身份/交易状态/订单规则；两币各取前一日 24 根小时 K 线；验证字节、唯一时戳、OHLC/closeTime/完整性。只在 source bytes 已提交并记 SHA 后推进模型。仅比较影响执行的 metadata 语义，不能因 serverTime 等非规则字段变化误停；若 tick/lot/precision/最小单/交易状态改变，BLOCKED_CONTROL 并报监督，不静默更新规则或继续冒充可执行。真实动态规则和费率到时仍需核验，本轮未访问官网/API。

拟议 endpoint 仅沿用旧源合同中的 `https://api.binance.com/api/v3/exchangeInfo?symbols=["BTCUSDT","ETHUSDT"]` 和 `/api/v3/klines`，后者固定 symbol、interval=1h、startTime=D00、endTime=(D+1)00−1ms、limit=24。它们是已用接口的未来预算草案，不是本轮新核实的当前 API 声明；实现前另获准核官方接口、再固定请求编码。无 key、无签名、无私有账户、无 WebSocket、无跳转/付费接口/真实下单。

## 4. 幂等、缺失、风险与停止

只需一个 Git 外日期目录与单个状态文件，无新数据库/daemon/API。每次任务 key=`candidate_hash/cost/UTC-data-day`，请求 key 再含 symbol/interval/start/end。请求前追加 attempt（成功/失败都收费）；响应临时文件原子改名并记 SHA。已有完整 source 不重复下载；相同日期相同 SHA 为 no-op，内容改版/同一 key 不同 SHA 拒绝，不覆盖原观测。

base/stress 从各自前一已提交状态推进；状态序列化须覆盖 cash、所有库存/basis、peak/latches、active/armed、residual、pending/exits、started/stops、marks/age、最后已处理小时及报告累计，不只存现金。一天的输出+新状态写同一临时批目录，成功后原子 rename 成 committed；启动先找已 committed key，存在则核 SHA 后不再计成交。崩溃在提交前，保留 failed/abandoned 尝试，使用完全相同输入从上次 committed 状态恢复，最多6个成本-日技术计算，不选择有利输出；不能重置峰值、锁存或预算。这里是待实现及合成验证的设计，不宣称当前已有 serializer。

没有网络/睡眠/超时：该次任务明确未完成，不合成实时订单；下次 heartbeat 醒来只在同一 W/E、额外12 GET、最多3个待收日、剩余时间内补已有授权日期，所有补采/计算标延迟。无后台循环、自行唤醒系统或改 Mac 权限。距最后成功日超过3个待收日、恢复额耗尽、HTTP429/418/身份或精度异常、状态 SHA 不一致，停止源入口并通知监督；不换域/换目录重置预算。停止后不靠结果选择恢复；新授权只能处理技术阻塞，不能移动 E 或改变候选，实际遗漏照记。

若当天源本身缺/短小时（而非作业尚未获取），接收缺口事实并按原冻结模型访问每个小时：缺 open 不成交，待入场过时取消，不删日/填价；85个连续完整日依赖恢复前禁新信号，旧 stops/expiry/residual 管理仍在有真实 open 时执行。缺日后再补到的历史修订不得改写已经提交的模型轨迹；保留为更晚获得的信息，不回填收益。暖启动期未开始评分时，可用首次获准接收且完整的历史日构造指标，但披露接收延迟。持仓沿最后原始价标 STALE/age，恢复先重估风险再行动。

10%/15% 锁存按冻结候选继续；任一成本轨迹 20% 观测 DD 穿越标 `RISK_LIMIT_BREACHED` 并停止整个候选的观察资格（不能挑另一成本继续），不虚构退出，保留截至停止的库存和价格可知性。会计不守恒/金额非有限/native绑定变化等工程错误标 `ACCOUNTING_UNRESOLVED`，不可把截断轨迹当完整经济证据。终态样本不足明确 `UNDERPOWERED`；缺源用 `BLOCKED_DATA`，两者可并列。期末持仓、已实现/未实现、估算退出费及 STALE 都分列，不能只汇总赢家。

## 5. 独立证据及 PR 收尾

180天、30个episode或95% bootstrap 都没有被证明是充分门槛。将来至少需要：候选与所有决策依赖在新价格之前固定；未用于选择、用途登记清楚的评分区间；可追溯真实来源/接收时间和完整成本；覆盖亏损、零成交、缺日和停止的完整轨迹；识别日收益序列自相关、两币共变、重叠持仓/episode、厚尾及暴露样本对选择的影响。若要统计资格，还必须在观察前明确 estimand、经济上有意义的最小效应/精度、错误率/多重比较控制与适用依赖模型，然后论证信息量/功效和区间方法；当前这些未建立，所以不承诺资格通过。新前向收益>=0最多是观察事实。组合互补性还需要同一合法日期下共享资本后的增量风险/成本证据，不能把两条独立钱包曲线相加。

PR140 当前69个文件全部落在 Issue139 的旧永续可行性、spot采集审计、模型/native映射、V3诊断和归因链；未新增 schema/business表、UI、服务或实时交易。旧采集/失败记录属于审计历史，不搬进最小候选运行链。固定索引列出必要文件 SHA 和旧结果引用；整个 PR 不删历史来美化范围。复核目标是此研究交付可追溯，不是声称69文件都是前向必要组件。
