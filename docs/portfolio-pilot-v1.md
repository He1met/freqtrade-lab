## 事前规则：由受控原生模板忠实实现

索引 t 是 UTC 日线刚闭合的日子，C/H/L 为该日收高低。所有 rolling 窗口要求完整、
有限、连续。日线形成后，订单最早在随后首个小时开盘执行；禁止把该小时收盘价用于下单。
实际迟到超过首个小时的日线信号作废，不能恢复后追补历史订单。

1. `r_t=log(C_t/C_(t-1))`；样本波动率用 ddof=1。
   `TR_t=max(H_t-L_t, abs(H_t-C_(t-1)), abs(L_t-C_(t-1)))`，ATR20为最近20个TR算术均值，
   不采用隐含 Wilder 初始化。每日可用274日预热；预热也必须具有明确训练读取用途且不碰保护值。
2. 趋势：`C_t>max(C_(t-N)..C_(t-1))` 为多，`C_t<min(...)` 为空，等号不触发。
   N仅42/63/84。持有多仓在 `C_t<min(C_(t-21)..C_(t-1))` 退出，空仓对称；
   入场时固定3×ATR20止损距离，42×24小时到期退出，不向不利方向放宽止损。
3. 反转：`z_t=log(C_t/C_(t-3))/(std(r_(t-60)..r_(t-1))*sqrt(3))`。
   |z| >= k，k仅1.5/2/2.5，取反方向。波动为零不入场。
   入场决策时冻结最近五个已闭合收盘 `mean(C_(t-4)..C_t)` 为目标；
   多仓在后续日收盘 >= 目标退出、空仓 <= 目标退出；2×ATR20固定止损，120小时到期。
   若目标已在入场价不利侧则跳过，不人为创建即时止盈交易。
4. 每个家族每币仅一个逻辑持仓；持仓时忽略同方向新增信号。退出优先于进入。
   止损后至少等待一根完整日线。退出决策时不重入；下一日才允许新信号。
   小时内止损与其它条件冲突时按原生不利顺序计；跳空按原生可成交假设并加保守滑点。
   日线退出条件只在闭合后生效。任何不能被原生引擎表达的上述规则都是实现阻塞，不能自行撮合替代。

### A/B/C与共享资金

A-trend、A-reversal各自是同时覆盖两币的一份独立1000钱包账户；每币止损风险预算1%权益。
B/C一份1000钱包内四逻辑单元，各为0.5%权益，家族间固定等风险。
逻辑目标数量=`当时账户权益×风险份额 / 入场ATR止损距离`，方向附符号。
入场数量冻结，不因为之后ATR下降自动加仓；开/平、C风险变化、风险预警和名义上限引起目标变化。
每日使用可得权益检查所有目标，先限制每币40%，再按比例缩到总名义80%；
现有敞口超限则减仓。风险额度不足不转移给其它家族。账户权益包含小时mark未实现盈亏、费用与funding。

B/C对同币四逻辑贡献先相加净额（实际每币最多一个净仓），相反信号抵消，
总资金不足按比例缩减。家族内部虚拟记录只作信号及归因，不能算成真实成交或自然事件样本。
方向翻转先用一笔关闭实际净仓，原生确认关闭后最早下一小时开反向仓，不在同bar凭空翻转。
家族退出后重新计算净额；不得在内部虚拟成交上收取真实手续费或funding。
单一原生实例、同一钱包和同一时间轴是B/C必须证明的条件，`--strategy-list`不是该证据。

C乘数：`sigma20_t=std(r_(t-19)..r_t)`；
`raw_m_t=min(1, median(sigma20_(t-252)..sigma20_(t-1))/sigma20_t)`。
零/缺失波动不增加风险；有效m降低立即使用新值，恢复最多每天增加0.1且不超过raw_m。
首次有效m取raw_m。m应用于B逻辑目标，每日最多调整一次；不按近期赢家改变权重。
同方向增减仓必须真实经过原生 position adjustment 并收成本。

最小量：MARKET订单按`floor(abs(target_qty)/step_size)*step_size`取整；
数量和名义低于适用门槛跳过、不放大，超过最大数量拒绝并记录。读取LOT/MARKET适用性，
不能把quantityPrecision当step。执行时以可得mark校验最小名义；缺mark不下单。
不能执行的减仓/残余仓位必须保留在权益风险中并记执行失败，不能假定已平。
当前规则快照不能证明历史交易所规则；历史元数据缺口在训练中明确假设，不能标实盘可执行。

对照：现金不需原生调用；市场暴露为固定BTC/ETH各40%权益、1x long，
日线闭合后次小时调整、同成本/最小订单；风险匹配B为**事前固定0.5×B逻辑风险**，
不通过观察C路径后拟合权重。两者总敞口相差需同时报告，0.5倍只是假定风险量级匹配，
不声称事后实现波动精确相同。所有对照使用同样的风险停止规则。

### 成本、停止及恢复

原生Taker费是已计成本，不重复扣；以实际成交数量/价格重算毛价差、fee、
滑点代理及有符号funding，再与原生权益核对。资金费按实际净仓数量与结算associated mark计算，
未知日历/缺事件不填零，边界不确定采用不利包含而不领取不确定credit。
压力仅手续费/滑点翻倍，真实funding不机械翻倍；原生和审计两个口径分别报告。
具体结算舍入模式在评分前补证；资料不能支持则继续 UNKNOWN，不提前评分。

小时mark检查DD；峰值不重置。DD>=10%风险预算减半且本段不自动恢复；
DD>=15%停止新增、下一可执行小时按原生路径退出，余下区间现金并保留影子记录；
DD>=20%记录风险目标突破并锁定。发生缺失/过期数据禁止加风险，持仓按现有止损管理，
未确认平仓仍算持仓。仅技术数据故障在连续三次完整小时检查通过后恢复，
过期信号丢弃。**本试点经济/回撤停用不自动恢复、不重新分配额度。**
这比长期方案的候选恢复机制更窄，用于避免首试点再引入未验证自由度。

## 训练、选择、预算与前向

24月是当前设计建议，窗口必须在价格读取前绑定；不是强制为凑时长挪用保护窗。
范围中从未登记且未保护的历史可在本授权下事前登记为新训练用途；
`allowed_seen`表示“允许作为探索/学习的数据”，不表示原始行情已读过或源质量已合格。
既有已见范围可研究学习，但不能重写旧终态或冒充旧确认重放。
跨币同日历、跨交易所同资产和LLM历史知识均披露为学习偏差；不能宣称全局未见。

设池起点S为月初，结束S+24月（半开区间）。第i折i=0..3训练[S+3i月,S+(12+3i)月)，
验证[S+(12+3i)月,S+(15+3i)月)。每折重新1000钱包、不携带前折仓位，预热不交易；
窗口末按原生强制退出并计成本，边界截断交易不计自然完整样本。四段验证日期不重复，
但共享历史、参数与市场状态带来的依赖必须保留，不能标成独立确认。

每折在训练数据上每家族三个版本：先要求成本后net>=0、DD<=20%、来源/因果/成本有效且非零成交，
再按`365*mean(日净收益率)-1.5*365*sample_variance(日净收益率)`选最高，
完全并列中央参数优先、然后数值升序。无候选的家族保持现金，不把额度转给另一家族。
样本数不足独立标 UNDERPOWERED，不自动按负收益淘汰，也不宣布经济资格。
最终参数依据四折**训练**效用均值，要求各训练折满足上述资格；不用验证结果重新挑参数。
四折验证检验整个固定选择过程，最终全池诊断不改变选型。

如果原生实现只能拆币，则预算和研究合同失效，必须评分前修订，不能偷偷追加。

每次同索引重采两序列并重算上述效用差，95%百分位区间。

## 控制元数据接口

`portfolio-window-metadata-v1`恰六字段：schema、ledger_sha256、restrictions_complete、
pool、allowed_seen、protected。pool={start,end}；两列表每行恰
{symbol,start,end,evidence_sha256}。日期YYYY-MM-DD，UTC半开；allowed_seen必须BTCUSDT/ETHUSDT；
protected可为具体标的或`*`（有证据的全局禁用，不能因为“相关”自行写*）。
授权需覆盖评分及274日预热。`restrictions_complete=false`强制阻塞；
声明true不是密码学证明，后续执行必须核验引用账前缀、新登记和原始源。
已知缺口不能伪造空protected列表。本模块不读取原始全局异构账、不做通用迁移。

`portfolio-exchange-metadata-v1`恰schema、observed_at、source、response_sha256、symbols。
来源固定`https://fapi.binance.com/fapi/v1/exchangeInfo`，时间明确UTC、非未来且24小时内。
symbols恰两币，每币字段symbol/status/contractType/quoteAsset/marginAsset/
min_notional/min_qty/max_qty/step_size/tick_size，十进制均字符串。
这是可审阅的匿名响应归一化声明，不替代原响应核验；maxQty/step来自适用MARKET_LOT_SIZE、
tick来自PRICE_FILTER，min_notional来自MIN_NOTIONAL。结算精度、账户资格仍UNKNOWN。
[Binance官方合约过滤器说明](https://developers.binance.com/zh-CN/docs/products/derivatives-trading-usds-futures/common-definition)。

当前审计与测试、逐次过程见 [Issue #109](https://github.com/He1met/freqtrade-lab/issues/109)
及 [首切片验收记录](issue109-portfolio-admission-receipt.md)。
