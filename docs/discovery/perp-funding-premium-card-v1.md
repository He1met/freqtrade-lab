# BTC/ETH 方向持续性与已结算资金费/premium 关系卡 V1

本卡于 2026-09-08 15:53:49 UTC、V2 退出对照结果产生前登记。准备阶段仅阅读已有代码、数据目录和协议；没有读取新的历史价格结果来选择阈值，没有运行市场回测。仅在 V2 换手分支按其预登记规则关闭、监督调度实际领取预算后执行。

假说是：24h 突破与方向持续性提供价格延续线索；与方向相反的已结算 funding 和 premium 可能表示衍生品侧相对不拥挤，在延续交易中减少 carry 成本。这只是可证伪的推断，既非未来资金费预测，也非现货/合约套利。负 funding 下做多、正 funding 下做空可能恰好追入正在衰竭的价格反弹；premium 过滤还可能只减少敞口，不能自动解释成增量 alpha。

语义来源是已核验的 [Binance USD-M 市场数据文档](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data) 及本仓库 [数据审计](../research/perp-data-audit-v1.md)：历史 funding 是实际结算记录，premium 是官方 premium index 的 OHLC，并非可成交价差。正 funding 的成本符号来自原生现金流 `-signed_quantity * rate * settlement_mark`；下一次费率和下一次结算间隔均不由最后一笔记录保证。

仅两项预登记对照，均继承父 persistence 的 24h 入场、阈值 0.25、12h 反向退出、72h 上限、1x、统一钱包和全部成本，不采用 V2 结果选择更有利的退出尺度：

1. `carry_nonpaying`：做多仅在最近已可用的已结算 rate ≤ 0；做空仅 rate ≥ 0。零值保留。过去不付费不意味着未来免费。
2. `carry_premium_agree`：在第一项上再要求同一信号小时已闭合 premium close 做多 ≤ 0、做空 ≥ 0。零是价格/carry 方向边界，无分位数训练或网格。

历史 funding `available_at = settlement + 1h`，premium `available_at = candle open + 1h + 60s`，都仅属保守历史假设、没有当时版本。每个信号源小时 t 在 `t+1h+60s` 形成决策，native 最早 `t+2h` 成交。资金费 as-of 连接只取该决策时已可用的最新事件，事件年龄超过 12h 或 premium 缺失/尚不可用时禁止该小时入场；完整评分窗出现该情形则报告 `BLOCKED_DATA`，不能补零。实际前向还必须使用 `max(assumed_available_at, fetched_at)`，这份历史 runner 不得被当作前向信号执行器。

父 12h 已完成结果只引用并验 SHA，不重新计算。先做合成时点/未来扰动/未知值门控及最多一次合成原生消费者测试，再以实际冻结代码/协议/数据 SHA 领取两变体预算。两币各 18 个月已曝光历史仅是开发样本；OI 和链上不拼入此次模型，也不充当独立证据。

报告必须拆分毛价差、Taker、滑点假设、真实结算资金费、净额、小时 MTM 回撤、换手、资金占用、币种/多空贡献、周期数和同步 72h 簇。24h 标签的父信号/两过滤集合只作重叠事件描述；过滤改善而事件毛效应与每单位敞口质量未改善，应明确可能仅是少做。20% 为风险目标，略高需解释，不是 20.1% 自动拒绝。

停止规则：两项净额都不支持或可用样本不足时关闭这两个固定符号门控，不继续调 rate/premium 阈值；保留正负与样本限制。若有成本后支持，唯一优先为该家族单候选的未来独立确认准备，需要在未来开始前另行绑定确认协议，不能挤入仅准入原价格家族的既有冻结窗。若两项关闭，唯一优先为完整历史数据上的“持续方向下的已闭合 premium 变化”机制新卡，必须先登记一个固定尺度和有限预算，不能静默在本轮增加第三变体；若无法给出新机制，就停止市场计算并继续可靠增量留存。
